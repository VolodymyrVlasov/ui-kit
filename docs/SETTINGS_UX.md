Доповнює `docs/ROADMAP.md` як окрема "Фаза 0.5" — доопрацювання самого редактора теми (Кольори/Типографіка/Розміри на `settings.html`), перед тим як переходити до Фази 1 (генератори компонентів). Якість цього редактора впливає на всі майбутні прев'ю компонентів, тому має сенс закрити її окремо.

## Save / Load / Reset — зворотний зв'язок

**Проблема:** кнопка "Зберегти" зараз просто завантажує `config.json` файлом без жодного підтвердження. "Завантажити" показує `window.alert` лише при помилці. "Скинути" — взагалі без відгуку.

**Рішення:** додати `UIKit.showToast()` (вже є в kit.js, використовується в інших місцях) на успішні Save/Load/Reset, і залишити чіткіше повідомлення про помилку через той самий toast замість `window.alert` для Load.

## Кольори

### Архітектурне рішення: справжні hover/disabled токени

Зараз hover — це прозорість базового кольору (`hsl(var(--primary) / 0.9)`), а disabled — просто `opacity: 0.5`. Жодних окремих токенів немає.

**Вирішено:** додати явні `-hover` і `-disabled` токени для кожної інтерактивної (actionable) кольорової ролі. Це великий рефактор — торкається `theme.css` (нові токени) і CSS усіх компонентів, що мають ці стани (кнопки, інпути, селекти, вкладки, бейджі, алерти тощо), не лише кнопок.

Структурні/нейтральні ролі (background, card, border, input, ring, muted) hover/disabled не отримують — це не actionable елементи.

### Повний набір токенів (light + dark, через верхній перемикач тем)

**Основа**
- `--background`, `--foreground`
- `--border`, `--input`, `--ring`
- `--muted`, `--muted-foreground`

**Картки**
- `--card`, `--card-foreground`

**Кнопки / інтерактивні ролі** (кожна: база + текст-на-ній + hover + disabled)
- Primary: `--primary`, `--primary-foreground`, `--primary-hover`, `--primary-disabled`
- Secondary: `--secondary`, `--secondary-foreground`, `--secondary-hover`, `--secondary-disabled`
- Accent: `--accent`, `--accent-foreground`, `--accent-hover`, `--accent-disabled`
- Destructive: `--destructive`, `--destructive-foreground`, `--destructive-hover`, `--destructive-disabled`
- Success: `--success`, `--success-foreground`, `--success-hover`, `--success-disabled`
- Warning: `--warning`, `--warning-foreground`, `--warning-hover`, `--warning-disabled`

Це +24 нових токени порівняно з поточним станом (6 ролей × hover + disabled).

### Порядок і подача в інтерфейсі (від загального до детального)

1. Верхній перемикач: **Світла тема / Темна тема** (лишається як є)
2. Група "Основа" — фон секцій/боді/контейнерів, з живим міні-прев'ю (просто пофарбований блок з текстом)
3. Група "Картки" — з живим прев'ю справжньої `.card`
4. Група "Кнопки" (по одній ролі за раз: Primary → Secondary → Accent → Destructive → Success → Warning) — кожна роль показує: колір фону, колір тексту, hover, disabled, і одразу живе прев'ю справжньої кнопки цієї ролі в усіх 4 станах (звичайна/hover/focus/disabled) поруч
5. Група "Службові" — border/input/ring, з прев'ю (рамка інпута, фокус-кільце)

### Вирішено (уточнення)
- Success/Warning НЕ отримують кнопкового варіанту (`btn-success`/`btn-warning` не додаємо) — ці ролі лишаються тільки в alerts.css/badges.css, і саме там отримують hover/disabled токени.
- Hover/disabled токени додаються одразу в усіх інтерактивних компонентах (buttons, inputs, selects, tabs, alerts, badges), а не лише в кнопках — це більший рефактор, робимо його зараз, а не розтягуємо по Фазах 1–4.
