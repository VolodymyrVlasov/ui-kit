# UI KIT

## Мета

UI KIT — веб-утиліта для вибору параметрів теми оформлення та конструювання компонентів інтерфейсу з подальшим копіюванням готової верстки у робочий проект.

Це не CSS-фреймворк для підключення "як є" — це інструмент-конструктор: користувач налаштовує тему й компоненти візуально, копіює отриманий HTML/CSS у свою верстку і далі наповнює реальним контентом самостійно.

## Концепція

### Вкладка "Тема оформлення"
- Кольори — акцент, основний, вторинний та інші токени
- Шрифти — пошук і підключення довільного шрифта з Google Fonts
- Розміри — відступи, падінги, гепи
- Система верстки — завжди flexbox

### Вкладка "Компоненти"
- Перелік компонентів (поточний + подальше розширення)
- Для кожного компонента — сторінка-конструктор: контейнер живого прев'ю, інструменти налаштування, вибір різновиду (наприклад: таблиця — з лініями/сортуванням/без рамки; кнопки — основні/другорядні/стани; текстові блоки тощо), кнопка копіювання готового HTML
- Параметри налаштування визначаються окремо для кожного компонента

## Результат роботи утиліти

1. **Архів теми** — завантажені шрифти, стилі, JS для поведінки інтерфейсу компонентів (не логіка сайту — лише UI-поведінка: таби, акордеони, копіювання тощо)
2. **Копіювання компонента** — налаштований компонент (без реального контенту) копіюється готовим HTML у робочу верстку для прототипування
3. **Файл сесії** — зберігає тему і стан налаштованих компонентів, можна підвантажити назад у кіт і відновити роботу

## Приклад використання

1. Обрав кольори, шрифти тощо → завантажив стилі → додав у свій проект
2. Обрав компонент лейауту, налаштував, скопіював HTML → вставив у проект → заповнив реальним контентом (тексти, картинки, посилання)
3. У вставлений лейаут додав інші компоненти (картки, таблиці, форми) тим самим способом

## Технічні принципи

- Верстка на flexbox. Лейаути визначають розміщення елементів; компоненти в десктопній версії заповнюють ширину батьківського елемента, висота — за контентом (якщо інше не задано в налаштуваннях компонента)
- Без build-кроку та серверного бекенду — відкривається в браузері як є (для функцій, що потребують `fetch`, — через локальний HTTP-сервер)
- Vanilla JS + легкі бібліотеки для складних задач за потреби (архів, парсинг тощо)
- Google Fonts: локальний список метаданих (назва + subsets, зокрема cyrillic-ext) для пошуку без API-ключа; CSS2 API для live-прев'ю; файли шрифтів довантажуються лише під час експорту вибраного шрифта
- Файл сесії відновлює тему **і** стан налаштованих компонентів

## Поточний стан (за результатами аналізу коду, серпень 2026)

Проект уже має робочий прототип конструктора (`js/builder.js`, вкладка "Інструменти → Конструктор"):

- Live-редагування кольорів (окремо світла/темна тема), типографіки (включно з довільним Google Font), spacing/radius/border/transition
- Генератори для 2 компонентів: таблиця, лейаут — з live-прев'ю і копіюванням HTML
- Save/Load/Reset конфігурації (`config.json`)
- Експорт `.zip`: "запечений" theme.css, компонентні CSS, kit.js, шрифти (включно з підключеним Google Font), стартовий HTML

Токенна система (`theme.css`), розбиття компонентів на окремі CSS-файли (15 шт.) та механізм копіювання HTML (`data-copy="html"`) — готова база, придатна для розширення без переробки.

### Що доведеться доробити

1. Генератори параметрів компонентів зараз охоплюють лише 2 з ~19 компонентів (таблиця, лейаут) — решту потрібно вивести на той самий патерн "налаштування → live-прев'ю → копіювання"
2. `initSelectSearch()` відсутній у перевикористовуваному `kit.js` — компонент select-search не працює "з коробки" при копіюванні в інший проект
3. Дублювання copy-логіки між `gallery.js`/`builder.js` варто об'єднати перед розширенням конструктора
4. Дрібні неузгодженості токенів (`--font-mono` без локального файлу, `--layout-sidebar-width` поза `theme.css`) — вирішити до того, як конструктор почне їх експортувати як "офіційні"

Детальний поетапний план розширення — окремим документом (крок 6 плану).
